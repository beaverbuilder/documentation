## The security model

Beaver Builder AI is a coding assistant that acts as the logged-in WordPress user, with exactly that user's permissions. It can't do anything you couldn't already do by hand, and nothing it makes goes live until you review and save it. This page explains where your data goes, who can do what, and the safeguards built into the plugin.

## Where your data goes

The AI runs through your own site and connects directly to your chosen AI provider using your own API key. Your prompts, content, and images are sent to that provider (Anthropic, OpenAI, or OpenRouter) to generate your design. They are not routed through, collected by, stored by, or used to train any Beaver Builder service.

- AI requests go from your server directly to the provider, using your own API key.
- The only data Beaver Builder servers receive is license and update information (license key, domain, and plugin version), sent over HTTPS.
- The plugin contains no analytics, telemetry, or tracking.
- Anthropic's and OpenAI's commercial APIs do not train on your inputs by default. OpenRouter's handling depends on the model provider it routes to; review its data policy if that matters for your content.

:::note
Content does go to your AI provider; that is how the AI works. It does not go to Beaver Builder. For details on Anthropic's data handling, see the [Anthropic Privacy Center](https://privacy.anthropic.com/).
:::

## API keys and usage

You bring your own API keys, so AI usage bills directly to your provider accounts. Beaver Builder does not meter, cap, or resell usage.

Your keys are encrypted (AES-256) before they are stored in your site's database, and they are never returned to the browser. The admin UI only shows whether a key is connected, not the key value. You enter and manage keys on the [Settings](configuration/settings.md) page.

## Permissions and who can do what

Beaver Builder AI uses WordPress's own roles and capabilities, so the AI can never exceed the permissions of the user running it. What a user can do with the AI matches what that user can already do by hand.

- **Generating blocks and editing code** (custom HTML, CSS, or JavaScript) requires the `unfiltered_html` capability, the same capability WordPress uses to allow raw HTML in posts. On a single-site install that means administrators and editors; on multisite, super admins only.
- **Editing content values** on existing blocks follows normal WordPress editing permissions for that page. Users without `unfiltered_html` cannot inject code: code fields are restored from the trusted saved copy, and editable values are sanitized.
- **Plugin settings, usage data, and MCP authorization** are limited to administrators.
- When Beaver Builder is active, access additionally respects Beaver Builder's own admin and unrestricted editing settings.

Developers can adjust who counts as a content creator with the `fl_ds_user_can_create_content` filter; see [Hooks](developer/hooks.md).

## Reviewing AI output

The AI never publishes on its own. Content it generates lands in the editor for you to review, and changes with wider impact, such as design token updates that restyle the whole site or removing a block, pause for explicit confirmation in the chat. Nothing reaches your visitors until you save or publish.

This review step is the practical safeguard behind every other control on this page. The AI acts within your permissions, and you decide what goes live.

## Connecting to the cloud service

Connecting your site to the Beaver Builder AI cloud service for MCP is optional and off by default. It activates only when an administrator explicitly connects the site, and it requires an active license.

- The connection uses standard OAuth 2.1.
- Your site stores no long-lived access or refresh tokens. It verifies each signed request on the fly, checking signature, expiry, issuer, audience, and which WordPress user the request maps to.
- A connected admin lets a cloud-connected AI agent act with that admin's permissions, by design, because it is a tool that builds pages. That access ends when you disconnect.
- Disconnecting removes the connection data entirely.

For setup details, see [MCP connection](configuration/mcp-connection.md).

## Forms built by the AI

Forms generated by the AI can email a recipient, post to a webhook, or redirect, and each path includes protections against common abuse.

- Webhook destinations are validated so they cannot reach internal or private servers.
- Email headers are scrubbed to prevent header injection.
- Submissions are rate limited and spam protected.

The form submission endpoint is the only public endpoint in the plugin; it has to be, so anonymous visitors can submit. It is protected by a honeypot, a signed time-trap token, rate limiting, and a duplicate-submission guard. See [Forms](build/forms.md#spam-protection).

## WordPress hardening

The plugin follows standard WordPress security practices for every data-changing action. These are the baseline protections the WordPress platform expects.

- Every data-changing action requires login plus the correct capability.
- Authentication uses standard WordPress cookie and nonce checks, which provide built-in CSRF protection.
- All database queries use parameter binding, which prevents SQL injection.

## A note on prompt injection

As with any AI tool, only paste or upload content you trust. A hidden instruction inside pasted text or a screenshot could in theory steer what the AI generates.

The safeguards limit the impact: the AI can only ever act within your own permissions, and its output lands in the editor rather than on your live site. The practical advice is to review what the AI generates before you save it, especially when you've pasted in content or screenshots from outside sources.
